# 后续可能更新

本页记录候选方向，不代表已经实现或确定实施。[返回开发指南](developer-conventions.md)。

## 数据库接入

现有[JSON 交换工具](../src/layerweave/tool/builtin/usage/exchange/README.md)支持项目、子树和对象导出、批量写回、复制时编号映射及工具表逻辑引用。交换 JSON 可以用于在不同数据库间搬运选定内容。

兼容的 SQLite 数据库可以通过现有入口直接打开；受支持的旧表结构由 initialize_database 显式升级。封装所需的 TOML 和 Python 类仍由运行环境提供，不存在数据库里。

如果后续需要直接适配不兼容版本或其他派生项目的数据库，再明确结构、配置和迁移关系。目前没有直接合并任意 SQLite 文件的通用适配器；优先复用已有交换格式和升级机制。

## 核心字段扩充前的兼容处理（待实施）

等确实需要给层或对象新增持久字段时，与该字段一并实现；当前没有新增核心列或通用迁移框架的计划。

目前 [normalize_record](../src/layerweave/support/storage/tables.py) 只为工具表的旧快照补后来增加的列，跳过核心种类。核心表新增列后，旧创建日志可能被撤销误判为整条记录冲突，旧删除日志恢复时可能因缺字段失败；日志本身仍保留。核心 SPECS 尚未像工具表一样声明 columns/default，修复需先明确新增列的默认语义，不能只移除跳过判断或把任意缺失值一律当作空值。

届时一并处理：

1. 对齐 SPECS、schema.sql、模型类、层／对象 base.toml 及受影响的存储和交换说明。需要类型检查的字段进入相应配置声明。
2. 为旧库编写明确的迁移步骤，由 initialize_database 等约定入口执行。仅修改建表 SQL 并重跑初始化不会给已有表自动补任意新列；普通 open_database 也不迁移。缺少新版所需列时，提供可识别的升级提示，避免裸 KeyError。迁移默认值应与旧快照补值一致。
3. 让撤销比较和恢复读取兼容后的核心快照，不改写原日志。补值仅解释结构升级；新增字段已被实际修改时，涉及创建／删除的撤销仍应报告真实冲突。
4. 验证新库读写、旧库升级、升级前的创建／修改／删除及其撤销和重做、旧交换文档导入、模型装载与配置检测；同时核对数据库列与字段声明的一致性。

若以后遇到加列和明确迁移步骤无法覆盖的结构变化，再评估 PRAGMA user_version 等版本化方案。此处记录的是后续扩充的配套工作，不表示相关兼容能力已经实现。

## 与完整版本的协作

本分支保留源码开发方式，核心、支撑、非视图工具和模板与完整版本同步。视图、MCP 服务和发行封装在[visualization 分支](https://gitee.com/emotion1354414/layer-weave/tree/visualization)维护；相关的发行渠道、远程接入和视图性能候选在该分支讨论，不在 main 重复实现。
