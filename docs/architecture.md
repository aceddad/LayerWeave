# LayerWeave 架构

LayerWeave 用层、对象、身份和关联组织内容。一个项目为层和对象提供身份范围；层组成树，对象归属于一个层，bind 表达可跨项目的普通引用。轴描述位置数值如何解释，基础结构不处理具体媒体。

## 三部分及依赖

| 部分 | 所在位置 | 负责什么 |
|---|---|---|
| 抽象核心 | src/core、src/models | Layer/Object、归属与引用字段、封装类型、类和继承约定 |
| 基础支撑 | src/support | TOML 适配、类装配、SQLite、读取、发号、事务、日志和公共 CLI 外壳 |
| 可替换工具 | tool/builtin | CDUR 协议、查询展示、编辑、内容检测、历史、撤销规划和帮助 |
| 外置技能 | tool/skills | 供 AI 按需阅读和使用的独立技能包 |

依赖方向为工具 → 支撑 → 核心。模型本身可以独立使用；支撑不导入内置工具。默认工具显式请求可选检测提供者，缺席时仍可写入。完整工具包可单独增减，包内保留自己的业务辅助代码。

封装有三层含义：核心表达类、类型和继承约定；支撑从 TOML 读取并合并、定位类、还原实例；检测工具判断内容是否符合约定。没有任何工具时，Title 记录仍能往返为 Title 实例。

## 可见的扩展结构

models/layers 与 models/objects 保存 Python 类，configs/layers 与 configs/objects 保存对应 TOML。一份 TOML 对应一个类，派生类与派生配置同时存在。记录继续保存相对配置根目录的 config_ref，例如 objects/title.toml；固定分区用于帮助 AI 寻找与开发，不改成另一套类型编号。

## 统一写入入口

工具决定要修改什么，support 的写会话完成真实修改。编号、记录和 before/after 日志在一个事务内提交；operation_id 由入口生成，日志从实际写入收集。工具返回的业务结果不会替代这些日志。

| 规则 | 执行位置和结果 |
|---|---|
| 项目存在、所属层存在、父层存在、存储非空列 | SQLite 外键与列约束，失败回滚 |
| 托管身份、可写字段、层/对象共用编号 | 支撑写入原语；恢复也维护编号上界，不复用已发编号 |
| 父链无环 | 支撑在提交前检查本批改变的父关系，以最终状态判断；成环回滚 |
| 普通位置落点 | 支撑写入时按当前轴精度处理，无精度时为 1e-6 |
| 原值迁移与恢复 | 支撑的明确入口保留位置值和必要的原身份，仍记日志并检查结构 |
| 内容类型、缺字段、重叠、接受对象类型、关联端点等 | 可替换检测工具，提交后报告；未安装则标记未检查 |

bind 是普通引用，目标失效不会使原始记录不可读。旧库中的父链环仍可查询、修复或删除；新增、复制或恢复不得重新提交环。基础类构造和属性赋值不增加自动检测。

## 保持轻量

当前仅使用 SQLite 和 TOML，不增加多后端、热卸载或依赖安装框架。CLI 共用模块和命令静态发现位于支撑层，卸掉帮助工具不会破坏其他工具的 --help。命令按文件声明发现，外置技能 route/tier/when 仅供 AI 阅读，不自动执行或检查路由。

原始读取与区间查询保持数值，不转换轴单位。具体工具的分割内容、跨界策略和引用映射见[使用说明](../tool/builtin/usage/README.md)。基础支撑的调用与扩展见[API](../src/support/API.md)，开发准备见[开发指南](developer-conventions.md)。
