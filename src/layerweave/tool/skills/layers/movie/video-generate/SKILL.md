# 视频生成

思路和老动画的"原画 + 中割"一样：关键帧自己准备（例如用出图 skill 按草图出成品），模型只负责补中间的动作。

脚本从本技能目录运行。传图片时需要 Pillow：`pip install -r requirements.txt`。

输出目录由调用的 AI 按项目管理，传入包含目录和文件名的 output，建议使用绝对路径；本技能没有固定输出目录。输入文件也建议使用绝对路径，避免切换工作目录后找错素材。

## 连接
- 地址：`--base-url`，或环境变量 `MINIMAX_BASE_URL`，写到 `.../v2` 这一级。必须提供。
- KEY：从环境变量读取，默认 `MINIMAX_API_KEY`；放在别的变量里时用 `--key-env 变量名`。不打印，也不接受写在命令行里。
- 如使用 LayerWeave 的 KEY 管理，先按[子进程调用示例](../../../../builtin/developer/keys/README.md#把连接交给技能子进程)选择条目并注入环境变量；KEY 不固定属于某个技能。
- 可以先用不存在的任务号探测查询响应，不生成视频：

```sh
python scripts/video.py ping
```

非 2xx 响应返回非零退出码，并保留 HTTP 状态和服务端原因。404 可能表示任务不存在，也可能表示路由不正确，不能据此判断连接或生成能力可用；已有真实任务时，用 wait 查询它。--base-url 和 --key-env 放在 ping/submit/wait 前面。

## 生成

```sh
python scripts/video.py submit <AI选定的输出目录>/片段.mp4 提示词.txt --first 首帧.png --last 尾帧.png --duration 4
python scripts/video.py wait <task_id> <AI选定的输出目录>/片段.mp4     # 中断后接着等、下载
```

- 把示意路径替换为本次项目的实际路径，含空格时加引号。提交前创建输出目录；收到任务号后先打印，再写同目录的 `片段.mp4.task`。完成后写 `片段.mp4.json`（模型、分辨率、时长、用量），并打印一行 JSON。
- 如果任务已提交、但本地任务号文件保存失败，错误中仍保留任务号。用 wait 继续，也可以另选下载路径；不要重新 submit。查询的 HTTP 错误立即报告，任务号保留，可在修正地址/KEY 后继续。
- 参考图／参考视频模式（`--ref-image`、`--ref-video`）不能和首尾帧同时用。
- 接口事实（2026-10 查询，以服务方文档为准）：
  - 图生视频的画面比例由首帧决定。
  - 图片宽高比需在 0.4–2.5 之间，边长 256–5760 px；请求体不超过 64 MB（脚本会把图片转成 JPEG）。
  - MiniMax-H3：768P／2K，4–15 秒。MiniMax-H3-Max：480P／768P，5–15 秒。

## 用法经验
- 镜头运动交给后期代码去做，提示词里写"固定镜头"，只让模型管角色动作。
- 首尾帧差得太大时，中间的形体会"融化"。大动作拆成几段，在中间补一张"中间原画"。
- 只给起点和终点时，模型倾向于走最短的路，可能直接穿过障碍物。实测：球从桌面上方到桌子下方，提示词写了"从桌边滚落"，生成的结果却是球直接穿过桌面落下。路线重要时，补一张路线上的中间原画，例如"球在桌边"。
- 节奏也交给后期：生成后再变速，让动作落在拍子上。
- AI 视频常见的问题是每帧都在动、像在滑，关键姿势处没有停住。用"看视频"那组工具（关键帧和停顿、自动摄影表）检查，再在后期按一拍二重排，在关键姿势处停住。
- 参考视频模式只实测过一次（用简单的 3D 人偶动作当参考）：动作顺序和停顿跟上了，角色正确；但构图没有跟随参考视频，还出现了一次参考里没有的转身。需要构图服从时，优先用首尾帧模式。
